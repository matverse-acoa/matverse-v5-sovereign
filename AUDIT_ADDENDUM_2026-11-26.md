# MatVerse V5 — replay and anchoring audit addendum

Date: 2026-11-26  
Scope: `omega-gate`, `replay-engine`, Merkle proofs, database ledger schema and Web3 anchor helper.

## Findings from source inspection

1. Replay Stage E called `evaluateOmegaGate`, which appends a new ledger event. A read/query operation could therefore mutate the ledger during replay.
2. Stage I used `db.query.ledger_events` although the database client was created without a Drizzle schema query API; errors were swallowed and converted to an empty event list. The requested start/end IDs were ignored.
3. Ledger values stored as integers (0–1000) were passed to `computeOmega` as if they were normalized 0–1 values.
4. The replay hash formula differed from the event creation hash formula. It could not verify the hashes generated by `omega-gate`.
5. Stage Ω compared a normalized score to `85`, and removed BLOCK states from the returned result. This both misclassified decisions and discarded negative states.
6. Merkle proof verification always concatenated current hash + sibling, so right-side leaves were not verified correctly. Odd-sized trees also omitted the duplicated sibling for the last leaf.
7. `verifyReplayAgainstChain` previously returned true for any 64-character hexadecimal string. It did not query an anchor or verify a transaction.
8. The Web3 helper used a placeholder Infura URL, a fixed 21,000 gas limit for a transaction with data, and no explicit submission authorization.

## Changes in this branch

- Added v2 canonical JSON event payloads, persisted alongside `hashVersion`; existing events remain version 1 and are classified as `UNVERIFIABLE_LEGACY`, not falsely reported as valid or corrupted.
- Added a non-destructive Drizzle migration. New writes use hash version 2; replay verifies payload-to-column correspondence and SHA-256.
- Reworked replay to use typed Drizzle selects, honor the requested ID range, verify chain continuity, normalize stored metrics, and use a pure evaluation function.
- Replay preserves PASS and BLOCK events, annotates gate outcomes, and never writes to the ledger or submits a transaction.
- Corrected Merkle proof direction and odd-leaf handling.
- External anchor submission now requires both explicit call-site approval and `MATVERSE_ALLOW_EXTERNAL_ANCHOR=true`, a configured Sepolia RPC URL, and chain-ID validation. Verification checks receipt success and the exact transaction data.
- Added a CI workflow for type checking, unit tests and production build.

## Promotion boundary

This addendum and its code changes do not establish production operation. Promotion still requires CI success, execution of the database migration in a controlled environment, a database-backed replay integration test, and independent validation of any externally submitted transaction. No transaction, deployment or external publication was performed by this work.
